LinearMatroidParity.hpp (optimized, 2026-11-10)
================================================

■ 問題
  d 次元ベクトルのペア (a_i, b_i) が m 個ある。
  選んだペアに属する全 2k 本のベクトルが線形独立となる最大 k を求める。
  返すのは重みなし最大サイズ。restore=true なら 0-indexed の選択添字を返す。

■ API
  using mint = atcoder::modint998244353;

  // 密ベクトル
  auto get = [&](int i, vector<mint>& a, vector<mint>& b) {
      // a,b は各呼出しで長さ d のゼロベクトルに初期化される。
      a[...]=...;
      b[...]=...;
  };
  auto ans = linear_matroid_parity<mint>(d,m,get,true);

  // 疎ベクトル
  auto get_sparse = [&](int i,
      vector<pair<int,mint>>& a,vector<pair<int,mint>>& b) {
      // a,b は各呼出しで空。 {座標,値} の列を push_back。
      // 同じ座標を複数回渡した場合は足し合わせる。
      a.push_back({j,x});
      b.push_back({k,y});
  };
  auto ans = linear_matroid_parity_sparse<mint>(d,m,get_sparse,true);

  ans.size      : ペア最大数（乱択の失敗時は過小評価の可能性あり）
  ans.selected  : 復元したペア添字を昇順で保持。restore=false なら空。
  戻された添字集合は常に線形独立で、選択不可能な解は返さない。

  追加引数：restore=false, uint64_t seed=自動, int trials=1
  例：linear_matroid_parity<mint>(d,m,get,true,1234567,3)

■ 計算量 / 対応型
  C++17 (GNU/Clang を推奨)、STL のみ。奇素数体 Mint が必要。
  必須: Mint::mod(), Mint(整数), + - * / == !=
  Mint::val() と Mint::raw(unsigned) があれば高速な処理経路に入る。
  mod <= 10^9 の場合に安全な uint64_t 積和を使用する。
  __int128 を使えるコンパイラでは積和の剰余を遅延させる。
  それ以外は通常の modint 演算にフォールバックする。

  最悪計算量：密入力 O(md^2+d^3) 時間、O(d^2) 追加メモリ。
  疎入力：歪対称行列の構築は O(sum nnz(a_i)*nnz(b_i))。
  復元で使う行列ベクトル積は nnz が小さければ O(d*nnz) に改善。
  全体の最悪計算量は O(md^2+d^3) のまま。
  入力ペアを丸ごと保持しないため、get コールバックを複数回呼ぶ。
  同じ ID のペアは毎回同じベクトルを返すこと。

■ 今回の変更
  1. 線形基底への挿入を 64-bit 遅延剰余で高速化。
  2. 密入力の歪対称行列構築で16ペア分をまとめて処理。
  3. 歪対称行列のランク・逆行列を2×2ピボット構造で高速化。
  4. 復元中のランク2更新を、行列要素あたり剰余1回に削減。
  5. 復元中の疎な行列ベクトル積を O(d*nnz) に削減。
  6. span 証明やその他の内積で 128-bit 積和を使用。

■ 正当性確認
  - d<=12,m<=12 のランダム 4500例を全列挙、密/疎、復元有無の4モードで比較（18,000検査）。
  - 一般 b-マッチングに帰着する小規模700例を全探索と比較。
  - ランダムな可逆歪対称行列900例で A A^{-1}=I を検査。
  - 分割マトロイド型大規模の復元数を検査。

■ 乱択・注意事項
  Lovasz の歪対称行列評価、span証明の一部がMonte Carlo。
  最適値を低く見積もることはあるが、不可能な解を返さない。
  試行回数を増やすとランク評価の失敗率を減らせる（時間増加）。
  mod 998244353 等の大きい奇素数を推奨。標数2には非対応。
